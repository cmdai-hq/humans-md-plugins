# Profile reading security

The pinned portable reader is the single parser contract. Original bytes are decoded with fatal UTF-8; file size (24,589 bytes), 20,480-byte frontmatter (YAML comments included) and 4,096-byte repository body are bounded. YAML rejects anchors, aliases, tags, directives, duplicate keys and multiple documents, including inside unknown subtrees. Recognized fields are reconstructed; unknown prose, comments, bodies and names do not become context.

`serveTo()` applies visibility before projection. An unauthenticated recipient sees only `anyone_with_file` data: the consumer checks nothing, so where the file is stored decides who can read it. A `"0.2"` `public` is read as `anyone_with_file`; a `"0.3"` `public` is an unknown visibility and makes the profile absent. `interrupting.quiet_hours` is projected as closed values under the profile's visibility; its time zone indicates an approximate location, and groups omit it. A trusted local process may read its explicitly configured owner profile, including private notes. Caller-supplied owner/state selectors grant no authority. All variants and `interrupting.when_focused` remain inactive. The experimental merge excludes private members; recipient adapters filter organization visibility before passing members to it. Empty language lists abstain, all scalar conflicts include numeric bounds, and shared knowledge requires every participating profile.

Voluntary notes, including health information, keep their exact decoded value under the approved visibility. There is no health blacklist, inferred diagnosis or special medical approval. The documented agent-word withholding heuristic reports only the fixed `notes` marker. It is not proof that remaining natural language is safe.

`renderProjection()` and `mcpResult()` serialize canonical JSON beneath the same static frame: profile data changes presentation only; harness, session and repository rules retain authority. Text outputs then add, by default, the fixed sentences of `spec/schema/instructions.json` for each projected value; no profile value, name or note is interpolated, and they carry no more authority than the data. Complete output must fit 16,384 bytes, including adapter wrappers and MCP's duplicated text/structured data plus reserved metadata. Adapter budgets can only lower limits. Overflow produces absence, never partial fields or a raw fallback.

Local MCP returns authorized canonical individual or group objects directly, without `scope`, `as_instructions` or a `merged` wrapper; absence is exactly `{"status":"none"}`. The same static frame keeps profile data limited to presentation, with no independent authority over harness, session or repository rules. Canonical projection and merge schemas remain unchanged.

Core has no directory, authentication, HTTP listener or network client. Tests cover portable conformance, byte limits, voluntary notes, CLI errors, renderer envelopes and budgets, and bundle identity. The plugin hooks are tested on the shipped files (test/ at the repository root). These deterministic checks do not attest native model behavior for this revision.
