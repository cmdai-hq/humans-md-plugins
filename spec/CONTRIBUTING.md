# Contributing and version policy

The canonical source is [cmdai-hq/HUMANS.md](https://github.com/cmdai-hq/HUMANS.md). The maintainer is **Tristan, for cmdAI**. The maintainer records acceptance, rejection or deferral of proposals and approves normative changes. A proposal or draft pull request does not itself approve a new contract.

Propose a change with its concrete use case, affected fields and readers/writers, privacy and authority implications, and examples of old and new behavior. Use synthetic profiles and source text; do not contribute real profiles, conversations, organization directories or secrets. Discuss via the repository's available issue/pull-request process; if access is restricted, that is an access limitation, not a different normative source.

A normative change includes matching prose, schemas, vocabulary/terms, expected vectors, changelog and conformance-matrix updates. Reviewers check writer and reader behavior separately, plus projection and group output schemas. Changes to authority, visibility, text serving or parsing require independent review. Record exact commands, source/tool/client versions, failures and limits; distinguish deterministic checks, documentation and native runtime/model trials. A green parser suite does not establish secure adapter behavior or user benefit.

All work remains a **draft** until an explicit maintainer release; no release tag exists. The declared format version is `humans: "0.3"`, and the current contract id is `0.3-draft.2026-10-18.1`. Draft revisions may change semantics under the same declared version, so a consumer must record the supported contract revision, canonical source commit and package checksums. [CONTRACT.json](CONTRACT.json) lists the reviewed file contents; downstream copies also pin the canonical commit that contains them.

After a stable release, field names, vocabularies, meaning, projection and acceptance rules change only with a new declared format version and explicit migration/compatibility vectors. Editorial corrections may retain the format version but get a new source revision. Published version artifacts remain immutable. Readers support only the versions they name; unknown future versions are absent, not guessed compatible.

Mirrors are generated from one pinned canonical revision. Verify each normative file's digest against the source manifest, check that the file inventory is complete, and fail CI on manual drift. A mirror must preserve relative links and schema `$id` / `$ref` resolution, serve the complete package and label draft status. A schema identifier is not evidence that its URL is deployed. Refresh the manifest with `node tests/check-structure.mjs --write-manifest` after intentional changes, then run the checks described in [tests/README.md](tests/README.md). Updating hashes is not a substitute for reviewing changed semantics.

The public package contains the format, schemas, examples, vectors and reference tools. It does not include a hosted organization server or proprietary product implementation. Preserve the applied [CC BY 4.0](LICENSE) and [Apache-2.0](tools/LICENSE) notices; changes here do not relicense earlier material. Prose fixtures follow the specification license; executable test scripts follow the reference-tools license. Do not imply the format's purpose adds restrictions to either license. The name and logo are excluded from these grants.
