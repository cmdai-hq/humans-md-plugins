# Documentary evidence and limits

The contract is a project design, not a claim that another format or vendor requires it. Prose, schemas and vectors in this repository are the normative source. SPEC.md gives no vendor-specific import or hook installation recipe; each adapter needs current documentation and its own runtime evidence.

| Subject | Primary source | Evidence used and limit |
|---|---|---|
| CODEOWNERS and approval | [GitHub: About code owners](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-code-owners) | Read live on 2026-10-13 (HTTP 200). It confirms that eligible owners need write access, required code-owner review needs branch protection/rulesets, any owner listed by the effective matching rule can satisfy that review, and CODEOWNERS itself needs protection. Enforcement, rulesets and bypass rights of any actual repository were not audited here. |
| Normative keywords | [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119), [RFC 8174](https://www.rfc-editor.org/rfc/rfc8174) | References for capitalized requirement words; no claim of IETF standardization of HUMANS.md. |
| JSON string encoding | [RFC 8259 § 7](https://www.rfc-editor.org/rfc/rfc8259#section-7) | JSON data encoding reference. The stricter deterministic encoding and byte budget are project requirements in SPEC § 6.3. |
| YAML and schemas | [YAML 1.2.2](https://yaml.org/spec/1.2.2/), [JSON Schema 2020-12](https://json-schema.org/draft/2020-12/schema) | Base formats. HUMANS.md defines a narrower subset plus checks that JSON Schema alone cannot express. Cited as references; no dated read is recorded. |
| Language vocabulary | [Library of Congress ISO code table](https://www.loc.gov/standards/iso639-2/ISO-639-2_utf-8.txt) | Downloaded 2026-10-13; the schema keeps its 183 ISO 639-1 entries. |
| Time zone vocabulary | [IANA tz database](https://www.iana.org/time-zones), release 2026e (`tzdata-latest.tar.gz`, file `zone.tab`) | Downloaded 2026-10-15. The schema keeps the 418 names of the third column of `zone.tab`, one per country region and including names such as `Europe/Oslo` that the database keeps as links, plus `UTC`. Node 26.10 `Intl.DateTimeFormat` accepted all 419 names. Validity uses this pinned list, not a runtime's time zone data. |
| Files that are not profiles (SPEC § 1) | [humans.txt](https://humanstxt.org), [attogram/agents](https://github.com/attogram/agents), [ayghri/i-have-adhd](https://github.com/ayghri/i-have-adhd), [thellmwhisperer/human.md](https://github.com/thellmwhisperer/human.md), [hehamalainen/Humans.md](https://github.com/hehamalainen/Humans.md), [Arcadi4/HUMANS.md](https://github.com/Arcadi4/HUMANS.md) | Repositories read on 2026-10-14; descriptions and example files re-checked with the GitHub API on 2026-10-15. human.md: allowed hours, breaks and session limits that a hook enforces on the owner's own agent; its example frontmatter has `framework: human-md` and no `humans` key. hehamalainen/Humans.md: “HUMANS.md teaches AI agents how to collaborate with humans on a repo: approvals, risk gates, communication format, definition of done, privacy, and blocked protocols.” Arcadi4/HUMANS.md: “Things you want to keep away from your coding agents.” attogram/agents: “./HUMANS.md - base instructions for Humans collaborating with an AI Assistant”. i-have-adhd: an output-style skill for coding agents. humans.txt (read 2026-10-13): “An initiative to know the creators of the website.” These projects change; re-check before each release. |

Native integration trials are recorded in [CHANGELOG.md](CHANGELOG.md) (Integrations), at the level they establish; no other model session is recorded as evidence here. A dated review finding or successful schema check is not proof that an adapter, deployment, identity service or privacy guarantee currently works. The source may be processed by a hosted compiler; this follows the described workflow and must be disclosed by the implementation, not inferred from where its CLI runs.

## Prior art with the same purpose

Read on 2026-10-16 (GitHub API, the projects' READMEs and the spacebot documentation page). Stars and dates as of that day. These projects change; re-check before each release. None of them declares a `humans` version, so a consumer treats their files as absent (SPEC § 1).

| Project | Source | What it is | Overlap with HUMANS.md |
|---|---|---|---|
| `HUMAN.md` in spacebot (spacedriveapp), 2,415 stars, created 2026-02-11; documentation page last changed 2026-08-11 | https://github.com/spacedriveapp/spacebot/blob/main/docs/content/docs/(core)/agents.mdx | A team agent's per-person profile at `humans/{id}/HUMAN.md`, rendered verbatim into the context of every agent linked to that person on every turn, with a 4,000-character budget by default (`human_profile_cap`): over it, the profile still renders with an over-budget warning; past twice the budget, it is truncated at a section boundary.
